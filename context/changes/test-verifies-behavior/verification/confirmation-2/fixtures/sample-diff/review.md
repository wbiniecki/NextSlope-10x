## Blocking reasons

- critical: access-control-scoping at src/main/java/com/nextslope/web/ProfileController.java:45 — New GET /profile/{userId} endpoint loads the profile form using the client-supplied userId path variable directly, never resolving ownership via CurrentUserService.requireUserId(principal). This exposes an owned route reachable without resolving ownership.
- critical: flyway-forward-only at src/main/resources/db/migration/V3__create_preference_profiles.sql:7 — V3 is an already-applied migration (no 'new file mode' header); adding the display_nickname column here edits it in place instead of shipping the change in a new V{n+1} migration. On Neon's free tier this cannot be rolled back once applied.
- high: ddl-auto-validate at src/main/resources/application.properties:16 — ddl-auto is changed from validate to update, explicitly to let a new entity/column apply itself without a migration. This defeats the fail-fast schema-mismatch protection that validate provided in every profile.
