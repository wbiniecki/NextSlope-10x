# Resort Catalog & Browsing (S-03) Implementation Plan

## Overview

Introduce the **resort domain** and let a signed-in user browse the full resort
list with key facts and open a single resort's detail view. This is the first
slice to need resort data, so it establishes the schema (Flyway `V2`), a JPA
entity + repository, and an **idempotent CSV-fed seed** drawn from the curated
40-resort Europe subset already shipped at
`src/main/resources/data/resorts-Europe-subset.csv`. No mark-visited, no admin
CRUD, no recommendation, no search/filter/pagination — those are later slices.

Roadmap: `S-03 / resort-catalog-browse`. PRD refs: **FR-006** (browse list with
key facts), **FR-007** (single resort detail view). Prerequisite **S-01**
(account-authentication) is done — every resort route is gated behind the
existing authenticated security chain.

## Current State Analysis

- **No resort domain exists.** Only the `user` domain is modeled
  (`com.nextslope.user.User`, `UserRepository`). There are no resort entity,
  repository, controller, templates, or migration.
- **Migration baseline is `V1__create_users.sql` only.** Flyway owns DDL;
  Hibernate runs `ddl-auto=validate` (`application.properties:15`). A new table
  requires a new `V2__` migration plus a matching entity, verified on both H2
  (PostgreSQL mode, local) and Postgres (Testcontainers/Neon).
- **An idempotent seed pattern already exists.** `com.nextslope.config.AdminBootstrap`
  is an `ApplicationRunner` that conditionally creates the admin account, guarded
  by an existence check and a `DataIntegrityViolationException` backstop. This is
  the exact shape to mirror for a "seed only when the table is empty" CSV loader.
- **Security gates new routes automatically.** `SecurityConfig` (filterChain,
  `:50-54`) permits an explicit public list and `.anyRequest().authenticated()`.
  Any new `/resorts/**` route is authenticated with no config change; an
  unauthenticated request is redirected to `/login`.
- **No shared Thymeleaf layout fragment.** `index.html`, `login.html`,
  `signup.html` each inline the Bootstrap 5 + HTMX CDN tags. The Bootstrap CSS
  `<link>` and the two `<script>` tags in `index.html:8-11,46-51` are the
  canonical CDN pins (with SRI hashes) to reuse.
- **The CSV is valid UTF-8 with 40 data rows + header.** Resort names carry
  en-dashes (`–` = bytes `e2 80 93`) and accents (`Isère`, `Sölden`,
  `Kitzbühel`). **One field is RFC-4180 quoted with an internal comma** — Tignes'
  `Season` = `"November - May, June - August"` — so a naive `split(",")` corrupts
  that row. The CSV header is:
  `ID,Resort,Latitude,Longitude,Country,Continent,Price,Season,Highest point,Lowest point,Beginner slopes,Intermediate slopes,Difficult slopes,Total slopes,Longest run,Snow cannons,Surface lifts,Chair lifts,Gondola lifts,Total lifts,Lift capacity,Child friendly,Snowparks,Nightskiing,Summer skiing`.
  Boolean-ish columns (`Child friendly`, `Snowparks`, `Nightskiing`,
  `Summer skiing`) hold `Yes`/`No`; numerics may be `0`.

### Key Discoveries:

- **Entity convention** (`User.java:23-57`, AGENTS.md): one package per domain,
  Lombok `@Getter/@Setter/@NoArgsConstructor/@AllArgsConstructor/@Builder`, JPA
  `@Entity` mapping a Flyway-created table, audit columns via Hibernate
  `@CreationTimestamp`/`@UpdateTimestamp` (not DB defaults) for cross-engine
  parity. → New `com.nextslope.resort` package.
- **Portable DDL** (`V1__create_users.sql`): `BIGINT GENERATED BY DEFAULT AS
  IDENTITY PRIMARY KEY`, `VARCHAR`, `TIMESTAMP`, `UNIQUE` — parses identically on
  H2 (PG mode) and Postgres.
- **Dual-engine verification standard** (AGENTS.md, `UserRepositoryPostgresTests`):
  a `@DataJpaTest` slice for fast local checks plus a `@Testcontainers` real-Postgres
  repository test prove the migration + mapping on both engines. CI runs both.
- **Controllers live in `com.nextslope.web`** (`HomeController`, `AuthController`);
  domain classes (entity, repository, seed loader) live in the domain package.

## Desired End State

A signed-in user navigating to `/resorts` sees all **active** resorts in a
single sortable table (ordered by country, then name), each row showing name,
country, top lift height, total slopes, total lifts, and the easy/medium/hard
difficulty mix, with a link to `/resorts/{id}`. The detail page shows the full
fact set for that resort. Unauthenticated requests to either route redirect to
`/login`. The resorts table is populated with exactly **40 rows** seeded from the
CSV; the seed is idempotent (re-seeds the wiped in-memory H2 on every dev boot,
skips on an already-populated prod DB). Verified by: `./gradlew test` green
(including the Postgres Testcontainers repo test and the seed/parse tests), and
manual navigation through `/resorts` → a detail page while signed in.

## What We're NOT Doing

- **Mark / unmark visited** — S-04. No visited state, no per-user resort join.
- **Admin create / edit / deactivate** — S-06. We add the `active` column and
  filter on it, but no write/admin UI; nothing flips `active` in this slice.
- **Recommendation / scoring** — S-05. We store raw slope counts and expose a
  derived difficulty-mix percentage for *display only*; no weighting/ranking.
- **Search, filter, pagination, grouping** — parked (roadmap §Parked). A flat
  sorted table is correct at 40 rows.
- **Showing the CSV `external_id` to regular users** — it is internal/admin
  metadata, stored but never rendered on the user-facing browse/detail pages.
- **Migrating `index/login/signup` onto the new layout fragment** — the fragment
  is introduced for the new pages only; the working auth templates stay as-is.

## Implementation Approach

A standard three-phase vertical build, each phase independently verifiable:

1. **Domain & migration** — `V2` migration + `Resort` entity + repository, with
   dual-engine repository tests. No seed, no UI yet.
2. **CSV seed loader** — add Commons CSV, then an idempotent `ApplicationRunner`
   that parses the classpath CSV (UTF-8, quote-aware) and inserts when the table
   is empty. Seed/parse/idempotency tests.
3. **Browse list & detail UI** — a shared Thymeleaf layout fragment, a
   `ResortController` with `/resorts` and `/resorts/{id}`, the two templates, and
   controller auth-gating + render tests.

**Identity model (refined):** the resort PK is an **internal generated surrogate**
(`id`, `BIGINT GENERATED BY DEFAULT AS IDENTITY`, mirroring `users`) used in all
user-facing URLs. The CSV's `ID` is stored as a separate **`external_id`**
(`BIGINT UNIQUE`, **nullable**) — admin/internal metadata only, the stable natural
key for seed dedupe, and the future home of the seed↔source link. Admin-created
resorts (S-06) will get an internal `id` with `external_id = NULL`. A generated PK
keeps `save()` a clean INSERT (no assigned-id merge/SELECT).

**Difficulty representation:** persist the raw CSV slope **counts** (beginner,
intermediate, difficult, total) losslessly; expose the easy/medium/hard
**percentages** as a derived (non-persisted) value computed from the three
difficulty counts so they sum to 100. Heavy scoring stays in S-05.

## Critical Implementation Details

- **CSV must be read as UTF-8 and parsed quote-aware.** Use an explicit UTF-8
  reader (`new InputStreamReader(resource.getInputStream(), StandardCharsets.UTF_8)`)
  and Commons CSV with header access. A `split(",")` approach will break the
  Tignes row (`"November - May, June - August"`) and risks mojibake on accented
  names. A round-trip assertion on Tignes' season and a UTF-8 name is the guard.
- **Difficulty percentages base.** Compute easy/medium/hard % off the **sum of the
  three difficulty counts** (not `Total slopes`, which can differ), then handle
  integer rounding so the displayed three sum to 100 (e.g., largest-remainder, or
  round two and derive the third). Guard against a zero denominator.
- **Seed idempotency is an empty-table guard, not an upsert.** Seed only when
  `count() == 0` (mirrors `AdminBootstrap`'s existence check). This re-seeds the
  wiped in-memory H2 on every dev boot and is a no-op on the populated prod DB; it
  deliberately does **not** clobber later admin edits (S-06 writes the same table).
  `external_id`'s UNIQUE constraint is the backstop against a double-insert race.

## Phase 1: Resort domain & migration

### Overview

Create the `resorts` table, the `Resort` JPA entity (full CSV columns + internal
surrogate PK + `external_id` + `active` + audit timestamps), and the repository
with the browse query. Prove the mapping on H2 and Postgres. No seed, no UI.

### Changes Required:

#### 1. Flyway migration for the resorts table

**File**: `src/main/resources/db/migration/V2__create_resorts.sql`

**Intent**: Create the `resorts` table holding the full curated fact set, keyed by
an internal surrogate PK, with the CSV id as a nullable-unique `external_id` and an
`active` flag defaulting true. Portable DDL only (parses on H2 PG-mode + Postgres).

**Contract**: New table `resorts`. Columns: `id BIGINT GENERATED BY DEFAULT AS
IDENTITY PRIMARY KEY`; `external_id BIGINT`; `name VARCHAR NOT NULL`; `country
VARCHAR NOT NULL`; `continent VARCHAR`; `latitude DOUBLE PRECISION`; `longitude
DOUBLE PRECISION`; `price INTEGER`; `season VARCHAR`; `highest_point INTEGER`
(top lift height); `lowest_point INTEGER`; `beginner_slopes INTEGER`;
`intermediate_slopes INTEGER`; `difficult_slopes INTEGER`; `total_slopes INTEGER`;
`longest_run INTEGER`; `snow_cannons INTEGER`; `surface_lifts INTEGER`;
`chair_lifts INTEGER`; `gondola_lifts INTEGER`; `total_lifts INTEGER`;
`lift_capacity INTEGER`; `child_friendly BOOLEAN`; `snowparks BOOLEAN`;
`nightskiing BOOLEAN`; `summer_skiing BOOLEAN`; `active BOOLEAN NOT NULL DEFAULT
TRUE`; `created_at TIMESTAMP NOT NULL`; `updated_at TIMESTAMP NOT NULL`. Constraint
`CONSTRAINT uq_resorts_external_id UNIQUE (external_id)` (NULLs are not equal on
either engine, so admin-created rows with NULL `external_id` are unconstrained).

#### 2. Resort entity

**File**: `src/main/java/com/nextslope/resort/Resort.java`

**Intent**: JPA `@Entity` mapping `resorts`, following the `User` Lombok +
timestamp convention, plus a derived (non-persisted) difficulty-mix accessor for
display.

**Contract**: `@Entity @Table(name = "resorts")` with Lombok
`@Getter/@Setter/@NoArgsConstructor/@AllArgsConstructor/@Builder`. `@Id
@GeneratedValue(strategy = GenerationType.IDENTITY) Long id`. Fields mapping every
column above (`externalId`, `name`, `country`, `continent`, `latitude`,
`longitude`, `price`, `season`, `highestPoint`, `lowestPoint`, `beginnerSlopes`,
`intermediateSlopes`, `difficultSlopes`, `totalSlopes`, `longestRun`,
`snowCannons`, `surfaceLifts`, `chairLifts`, `gondolaLifts`, `totalLifts`,
`liftCapacity`, `childFriendly`, `snowparks`, `nightskiing`, `summerSkiing`,
`active`). `@CreationTimestamp created_at`, `@UpdateTimestamp updated_at` (Instant,
as in `User`). A `@Transient` derived accessor returning the easy/medium/hard
percentage triple (small immutable holder or `int[]`/record) computed from the
three difficulty counts per the rounding rule in Critical Implementation Details.

#### 3. Resort repository

**File**: `src/main/java/com/nextslope/resort/ResortRepository.java`

**Intent**: Spring Data repository exposing the browse query (active-only, sorted
country then name) and an active-only single lookup for the detail view.

**Contract**: `interface ResortRepository extends JpaRepository<Resort, Long>`.
Methods: `List<Resort> findByActiveTrueOrderByCountryAscNameAsc()`;
`Optional<Resort> findByIdAndActiveTrue(Long id)`.

### Success Criteria:

#### Automated Verification:

- Build + full suite passes: `./gradlew test`
- App context boots with the new migration on H2: `./gradlew test --tests com.nextslope.NextslopeApplicationTests`
- New `@DataJpaTest` resort repository slice passes (save + `findByActiveTrueOrderByCountryAscNameAsc` ordering + `findByIdAndActiveTrue` excludes inactive)
- New Testcontainers Postgres resort repository test passes (migration applies + mapping validates on real Postgres), mirroring `UserRepositoryPostgresTests`

#### Manual Verification:

- Inspecting the H2 console shows the `resorts` table with all columns and the `uq_resorts_external_id` constraint
- `external_id` accepts NULL and rejects a duplicate non-null value

pause for manual confirmation before proceeding.

## Phase 2: CSV seed loader

### Overview

Add the Commons CSV dependency and an idempotent `ApplicationRunner` that reads the
classpath CSV as UTF-8, parses it quote-aware, maps each row to a `Resort`
(`active = true`, `external_id` = CSV `ID`, `Yes/No` → boolean), and inserts the
batch only when the table is empty.

### Changes Required:

#### 1. Commons CSV dependency

**File**: `build.gradle`

**Intent**: Add a well-supported CSV parser rather than hand-rolling RFC-4180
quoting (AGENTS.md favors popular, well-documented libraries).

**Contract**: Add `implementation 'org.apache.commons:commons-csv:1.14.1'` to the
`dependencies` block (latest stable on Maven Central; not managed by the Spring
Boot BOM, so pin it). Use tabs to match the file's existing indentation.

#### 2. Resort seed loader

**File**: `src/main/java/com/nextslope/resort/ResortSeedLoader.java`

**Intent**: On startup, populate `resorts` from the shipped CSV exactly once per
populated database — mirroring `AdminBootstrap`'s guarded `ApplicationRunner`.

**Contract**: `@Component implements ApplicationRunner`, constructor-injected
`ResortRepository`. `run(...)` returns early (logged) when
`resortRepository.count() != 0`. Otherwise loads
`classpath:data/resorts-Europe-subset.csv` via `ClassPathResource`, wraps the
stream in a UTF-8 `InputStreamReader`, parses with Commons CSV using the first
record as headers, maps each record to a `Resort` (header-name access for every
column; trim; `"Yes"` → `true` else `false` for the four boolean columns;
`external_id` from the `ID` column; `active = true`), and persists via `saveAll`.
Log the inserted count. The `external_id` UNIQUE constraint is the
double-insert backstop (catch/skip on `DataIntegrityViolationException`, as
`AdminBootstrap` does). Path/parse constants live in the class.

### Success Criteria:

#### Automated Verification:

- Full suite passes: `./gradlew test`
- Seed test asserts exactly **40** resorts after a boot against an empty DB
- Idempotency test asserts a second `run(...)` against a populated table inserts nothing (count stays 40) and does not throw
- Parse test asserts the Tignes row's `season` equals `November - May, June - August` (quoted comma preserved) and an accented name (e.g., `Sölden` / `Tignes - Val d'Isère`) round-trips intact (UTF-8)
- Boolean mapping test asserts a known `Yes`/`No` column maps to `true`/`false`

#### Manual Verification:

- `./gradlew bootRun` logs the seed insert count on a fresh start; restarting (H2 wiped) re-seeds without error
- H2 console shows 40 rows with correct names, seasons, and `external_id` values

**Implementation Note**: Pause for manual confirmation before proceeding.

## Phase 3: Browse list & detail UI

### Overview

Add a reusable Thymeleaf layout fragment, a `ResortController` exposing the gated
`/resorts` list and `/resorts/{id}` detail routes, and the two templates. The list
shows the key facts sorted country-then-name; the detail shows the full fact set.
The internal `id` is used in URLs; `external_id` is never rendered.

### Changes Required:

#### 1. Shared layout fragment

**File**: `src/main/resources/templates/fragments/layout.html`

**Intent**: A single reusable shell (head with the Bootstrap+HTMX CDN tags + a
top nav) so the new authenticated pages don't re-inline CDN markup; later slices
(S-04/S-05/S-06) reuse it.

**Contract**: A native Thymeleaf parameterized fragment (no layout-dialect on the
classpath) — e.g. `th:fragment="page(title, content)"` rendering `<head>` with the
exact Bootstrap CSS `<link>` + Bootstrap/HTMX `<script>` pins (SRI hashes) copied
from `index.html:8-11,46-51`, a Bootstrap navbar with a brand link to `/resorts`
and a sign-out `POST /logout` form (shown when authenticated, via the
`sec:authorize` namespace already used in `index.html`), and a body slot filled
via `th:replace="~{::content}"` / `th:insert`. New pages supply title + content.

#### 2. Resort controller

**File**: `src/main/java/com/nextslope/web/ResortController.java`

**Intent**: Serve the gated browse list and single-resort detail; 404 on an
unknown or inactive id.

**Contract**: `@Controller`, constructor-injected `ResortRepository`.
`@GetMapping("/resorts")` adds `findByActiveTrueOrderByCountryAscNameAsc()` to the
model and returns `resorts/list`. `@GetMapping("/resorts/{id}")` looks up
`findByIdAndActiveTrue(id)`, returns `resorts/detail` when present, otherwise
yields a 404 (e.g., throw `ResponseStatusException(NOT_FOUND)`). No security
config change — routes are authenticated by the existing `.anyRequest()` rule.

#### 3. Browse list template

**File**: `src/main/resources/templates/resorts/list.html`

**Intent**: Render all active resorts as one scannable, sorted table; each row
links to its detail page.

**Contract**: Uses the layout fragment. A Bootstrap table iterating the model
list (already ordered country-then-name) with columns: Name (link to
`@{/resorts/{id}(id=${r.id})}`), Country, Top lift height (`highestPoint`), Total
slopes, Total lifts, and the difficulty mix (the derived easy/medium/hard %).
`external_id` is not shown.

#### 4. Resort detail template

**File**: `src/main/resources/templates/resorts/detail.html`

**Intent**: Show the full fact set for one resort in a focused layout.

**Contract**: Uses the layout fragment. Renders the resort's full attributes
(name, country/continent, season, price, elevation high/low, slope counts +
derived difficulty mix, lift breakdown + totals, lift capacity, longest run, snow
cannons, and the Yes/No amenities), plus a back link to `/resorts`. `external_id`
is not shown.

#### 5. Permit-list regression sample

**File**: `src/test/java/com/nextslope/PermitListLockTests.java`

**Intent**: Keep the repo's permit-list lock aligned with the roadmap — the file
documents that each slice introducing a real gated route must add it to the
must-stay-gated sample list, so a future stray `permitAll()` widening can't
silently expose `/resorts`.

**Contract**: Add `/resorts` (and optionally `/resorts/1`) to the
`@ValueSource` of `mustStayGatedPathsRedirectAnonymousToLogin`. This complements
(does not replace) the route-specific MockMvc auth-gating assertion on
`ResortController` in success criterion 3.2.

### Success Criteria:

#### Automated Verification:

- Full suite passes: `./gradlew test`
- Unauthenticated `GET /resorts` and `GET /resorts/{id}` redirect to `/login` (3xx), asserted via MockMvc (pattern as in `AuthenticationIntegrationTests`)
- Authenticated `GET /resorts` returns 200, view `resorts/list`, and the body contains seeded resort names / fact columns
- Authenticated `GET /resorts/{id}` for a seeded id returns 200 and view `resorts/detail`; an unknown id returns 404

- `PermitListLockTests` includes `/resorts` in its must-stay-gated sample list and passes

- Detail page shows the full fact set and a back link; layout/nav renders correctly (Bootstrap styled, sign-out works)

## Testing Strategy

### Unit Tests:

- Difficulty-mix percentage derivation: counts → easy/medium/hard %, summing to
  100 under the rounding rule; zero-denominator guard.
- Boolean column mapping (`Yes`/`No` → `true`/`false`).

### Integration Tests:

- `@DataJpaTest` resort repository slice: ordering query + active-only single
  lookup (excludes inactive).
- Testcontainers Postgres resort repository test (dual-engine migration + mapping
  proof), mirroring `UserRepositoryPostgresTests`.
- Seed loader: count == 40 on empty DB; idempotent no-op on populated DB; Tignes
  quoted-comma season preserved; accented name round-trips.
- `ResortController` via MockMvc: auth-gating (redirect when anonymous), list
  renders facts, detail-by-id renders / unknown id 404, `external_id` absent from
  HTML.

### Manual Testing Steps:

1. Sign in; navigate to `/resorts`; confirm 40 rows sorted by country then name.
2. Open several detail pages (incl. Tignes — verify the season string and an
   accented name render correctly).
3. Sign out; hit `/resorts`; confirm redirect to `/login`.
4. Restart the app; confirm it re-seeds the wiped H2 with no error and the same 40
   rows.

## Performance Considerations

Trivial at 40 rows: a single unpaginated `SELECT ... ORDER BY country, name` and
single-row lookups. No caching, no pagination needed (parked until >~100 resorts).
Seed is a one-shot `saveAll` of 40 rows guarded by a `count()`.

## Migration Notes

- New forward-only migration `V2__create_resorts.sql`; never edit `V1`. No
  down/undo script (Neon free has no rollback).
- Seed is **data, not DDL** — it lives in app code (`ResortSeedLoader`), never in a
  Flyway file (AGENTS.md). The empty-table guard makes it safe on both the wiped
  local H2 and the persistent prod DB; it never overwrites admin edits (S-06).
