# NextSlope code review

**Blocked** — 5 blocking findings at or above `high`, out of 6 findings.

## Blocking reasons

- critical: access-control-scoping at src/main/java/com/nextslope/web/ProfileController.java:43 — New GET /profile/{userId} handler loads and renders another user's preference profile using a client-supplied userId path variable, never resolving ownership via CurrentUserService.requireUserId(principal). Any authenticated user can view any other user's profile by changing the id — an IDOR hole on a route family that previously carried no id at all.
- critical: flyway-forward-only at src/main/resources/db/migration/V3__create_preference_profiles.sql:7 — V3__create_preference_profiles.sql is an already-applied migration (no 'new file mode' in its diff header); adding the display_nickname column here edits it in place instead of introducing the column via a new V{n+1} migration. Neon's free tier has no rollback, so this is irreversible in production.
- high: constructor-injection at src/main/java/com/nextslope/profile/PreferenceProfileService.java:30 — profileAuditRepository is injected via field @Autowired on a @Service class instead of being added to the constructor-injected private final fields (@RequiredArgsConstructor), reintroducing field injection where the codebase has none.
- high: ddl-auto-validate at src/main/resources/application.properties:16 — spring.jpa.hibernate.ddl-auto is switched from validate to update, defeating the fail-fast schema-mapping check that was previously enforced in every profile and letting Hibernate silently alter the schema.
- high: flyway-forward-only at src/main/resources/db/migration/V6__create_profile_audit.sql:7 — id SERIAL PRIMARY KEY is Postgres-specific DDL, not the portable BIGINT GENERATED BY DEFAULT AS IDENTITY idiom used elsewhere in this repo; this risks failing to parse on H2 in PostgreSQL-compatibility mode, opening a dual-engine portability hole the migration set did not previously have.
